# 架构设计文档

## 1. 整体架构

Smart Farm System 采用 **边缘-云协同** 架构，分为三层：

```
┌─────────────────────────────────────────────────────────────┐
│                     云端平台层 (Cloud)                       │
│  Spring Boot 微服务 + MySQL + InfluxDB + Redis + EMQX       │
├─────────────────────────────────────────────────────────────┤
│                     边缘网关层 (Edge)                        │
│  树莓派: 数据聚合 + MQTT上云 + GPIO控制 + 继电器驱动         │
├─────────────────────────────────────────────────────────────┤
│                     感知执行层 (Device)                      │
│  ESP32 采集节点: 传感器数据采集 + WiFi通信                  │
│  继电器+水阀: 执行灌溉控制                                   │
└─────────────────────────────────────────────────────────────┘
```

## 2. 分层职责

### 2.1 感知执行层 (ESP32 + 传感器)

**职责：** 数据采集 + 设备执行

- ESP32 节点定时（60s/120s/300s 可配）读取传感器数据
- 通过 WiFi 发送到树莓派网关（HTTP 或 ESP-NOW）
- 每个节点可接入 4-5 种传感器
- 采用 Deep Sleep 模式降低功耗（可选）

**传感器接口：**

| 传感器 | 接口 | 采集参数 |
|--------|------|---------|
| DHT22 | 单总线 GPIO | 温度 (°C) + 湿度 (%) |
| FC-28 | 模拟 ADC | 土壤湿度 (%) |
| BH1750 | I2C | 光照强度 (lux) |
| MH-Z19B | UART (Serial) | CO2 浓度 (ppm) |

### 2.2 边缘网关层 (树莓派)

**职责：** 协议转换 + 数据聚合 + 边缘控制

- 接收多个 ESP32 节点上报的数据（HTTP Server 或串口）
- 数据聚合后通过 MQTT 上报到云端平台
- 接收云端下发的控制指令，通过 GPIO 驱动继电器
- 本地缓存断网数据，网络恢复后补传

**MQTT 通信模式：**
- 发布 (Publish)：传感器数据、设备状态、控制回复
- 订阅 (Subscribe)：控制指令、配置更新

### 2.3 云端平台层 (Spring Boot)

**职责：** 数据存储 + 业务逻辑 + AI 推理 + 实时推送

平台内部模块依赖关系：

                  ┌────────────────▼───────────────────┐

                  │  ┌─────────────┐  ┌─────────────┐ │

## 3. 数据存储设计

### 3.1 双数据库策略

| 数据库 | 存储内容 | 理由 |
|--------|---------|------|
| MySQL | 农场/地块/传感器配置、灌溉规则/记录、病害记录、告警 | 结构化业务数据，需要事务和关联查询 |
| InfluxDB | 传感器时序数据（每60s一条） | 高写入吞吐量，高效时间范围查询和聚合 |
| Redis | 传感器最新值缓存、告警去重、限流计数 | 低延迟读取，减少 InfluxDB 查询压力 |

### 3.2 InfluxDB 数据模型

```
Measurement: sensor_reading
Tags:
  - farm_id (农场ID)
  - field_id (地块ID)
  - sensor_id (传感器编号)
  - sensor_type (传感器类型: temperature/humidity/soil_moisture/light/co2)
Fields:
  - value (传感器数值)
Timestamp: 采集时间 (毫秒精度)
```

聚合 Measurement：
```
Measurement: sensor_hourly_agg
Tags: farm_id, sensor_id, sensor_type
Fields: avg_value, max_value, min_value
Timestamp: 整点时间
```

## 4. 核心流程设计

### 4.1 传感器数据采集流程

```
ESP32 采集 → WiFi → 树莓派聚合 → MQTT Publish → EMQX → 平台订阅
                                                         │
                                              ┌──────────┤
                                              │          │
                                    写入 InfluxDB    更新 Redis 缓存
                                              │          │
                                              │    更新传感器在线状态
                                              │          │
                                              └──── 阈值检查 → 告警(如超限)
                                                         │
                                                  WebSocket 推送看板
```

### 4.2 自动灌溉控制闭环

```
┌──────────────────────────────────────────────────────────────────┐
│  定时任务 (每5分钟)                                                 │
│  ┌──────────────────────────────────────────────────────────┐   │
│  │ 1. 查询所有启用的灌溉规则                                  │   │
│  │ 2. 对每条规则执行条件判断:                                  │   │
│  │    a. 当前时间 ∈ 允许灌溉时段?                              │   │
│  │    b. 当天灌溉次数 < 最大次数限制?                         │   │
│  │    c. 无正在进行的灌溉?                                     │   │
│  │    d. 未下雨(如启用雨天跳过)?                               │   │
│  │    e. 当前土壤湿度 < 阈值?                                  │   │
│  │ 3. 全部满足 → 计算灌溉时长(基于湿度缺口)                     │   │
│  │ 4. 安全截断: 不超过最大时长                                 │   │
│  │ 5. MQTT 下发 OPEN 指令到树莓派                              │   │
│  │ 6. 创建 IrrigationLog (状态=PENDING)                        │   │
│  └──────────────────────────────────────────────────────────┘   │
│                                                                   │
│  树莓派收到指令 → GPIO HIGH → 继电器闭合 → 水阀开启 → 灌溉          │
│  灌溉完成 → 树莓派 MQTT Publish control/resp                     │
│                                                                   │
│  平台收到回复 → 更新 IrrigationLog(状态=COMPLETED, 实际时长, 用水量) │
│  如果失败 → 触发灌溉异常告警                                       │
└──────────────────────────────────────────────────────────────────┘
```

### 4.3 AI 病虫害识别流程

```
前端上传图片(Base64) → DiseaseController
  → DiseaseDetectionService
    → DiseaseAiClient (HTTP POST)
      → YOLOv8 FastAPI 服务
        → 模型推理
        → 返回检测结果(class_name, confidence, bbox)
      ← 解析AI返回
    → 生成处理建议(根据病害类型)
    → 保存 DiseaseRecord 到 MySQL
  ← 返回 DiseaseResultVO
```

## 5. 非功能设计

### 5.1 可靠性

- MQTT 自动重连 (`automaticReconnect=true`)
- MQTT 会话保留 (`cleanSession=false`)，断网消息不丢失
- InfluxDB 写入失败不影响主流程（catch + 日志）
- Redis 告警去重，避免同一告警5分钟内重复

### 5.2 安全性

- 灌溉安全限制：最大时长、每日次数、雨天跳过、防重复触发
- 告警分级：INFO/WARN/CRITICAL/URGENT，不同级别不同处理优先级
- API 统一异常处理，避免敏感信息泄露

### 5.3 扩展性

- 传感器类型枚举可扩展（新增类型只需添加枚举值）
- AI 识别支持本地/云端双模式切换
- MQTT Topic 使用通配符订阅，新增农场无需修改平台
